# E-Commerce Backend Review And Refactor Notes

Last reviewed: 2026-07-07

Reference: `ecommerce-api-spec.docx.pdf`

## Executive Summary

This repository is a single-package Node.js backend for an e-commerce and social-shopping platform. It exposes a REST API with Express 5 and TSOA, persists data with TypeORM/PostgreSQL, authenticates with JWT access and refresh tokens, integrates Paystack for checkout and vendor onboarding fees, and uses S3 pre-signed URLs for product images, avatars, and vendor documents.

The current backend is already close to the attached specification in structure and feature coverage. The strongest areas are the domain-module layout, entity coverage, JWT auth, product/cart/order flows, vendor onboarding state machine, S3 upload flow, admin dashboard APIs, and social friend/cart-sharing APIs.

The refactor pass focused on low-risk, high-impact changes:

- Fixed generated route ordering for static routes that were being shadowed by dynamic `/:id` routes.
- Enforced admin authorization for category mutations and `/orders/admin/all`.
- Made public product detail match browse behavior by returning only active, approved products.
- Centralized runtime configuration through `src/config/env.ts`.
- Improved Paystack webhook verification by validating the raw request body.
- Replaced hardcoded checkout tax with configured `TAX_RATE`.
- Removed unused manual DTO validation code now superseded by TSOA validation.
- Regenerated `src/routes.ts` and `src/public/swagger.json` from source controllers.

## Architecture

The backend follows the domain module pattern described in the spec:

- `src/app.ts` creates the Express app, applies security/logging/body middleware, mounts Swagger UI, registers generated TSOA routes, and installs the global error handler.
- `src/server.ts` initializes TypeORM and starts the HTTP listener.
- `src/modules/*` contains controller/service/DTO triplets per feature domain.
- `src/entities/*` contains TypeORM entities for auth, catalogue, commerce, vendor onboarding, and social data.
- `src/config/*` owns validated env, database, Paystack, and S3 clients/helpers.
- `src/middlewares/*` contains TSOA auth integration, role guard helper, rate limiting, and error handling.
- `src/routes.ts` and `src/public/swagger.json` are generated by TSOA and should not be edited manually.
- `src/tests/*` contains Jest/Supertest integration coverage.

## Turborepo / Turbo Stack Note

This backend repository is not currently a Turborepo/Turbo workspace. There is no `turbo.json`, no package-workspace root, and no multi-package build graph in this backend folder. It is a standalone npm package named `ecommerce-api`.

If the frontend lives in a separate Turborepo outside this folder, this API would be one deployable service consumed by that frontend. Inside this backend repo, the build lifecycle is simple:

- `npm run build:routes` runs `tsoa spec-and-routes`.
- `npm run build` regenerates routes/docs and compiles TypeScript.
- `npm run dev` runs the API with `ts-node-dev`.
- `npm test` runs integration tests serially.

## Frontend Integration Model

The frontend consumes this backend through JSON REST endpoints generated from TSOA controllers. Typical integration patterns are:

- Store the `accessToken` and `refreshToken` returned by `/auth/register` or `/auth/login`.
- Send `Authorization: Bearer <accessToken>` to protected routes.
- Use `/auth/refresh` when the 15-minute access token expires.
- Browse approved products through `GET /products`.
- Upload images/documents by calling `/uploads/presign`, uploading directly to S3, then calling `/uploads/confirm`.
- Start checkout through `/orders/checkout`, then redirect the customer to the returned Paystack `paymentUrl`.
- Rely on Paystack webhooks to mark orders paid and advance vendor fee payments.

## Workflow Review

### Auth And Sessions

Files:

- `src/modules/auth/auth.controller.ts`
- `src/modules/auth/auth.service.ts`
- `src/modules/auth/auth.dto.ts`
- `src/entities/User.ts`
- `src/entities/RefreshToken.ts`
- `src/utils/jwt.ts`
- `src/utils/hash.ts`
- `src/middlewares/authenticate.ts`
- `src/middlewares/rateLimiter.ts`

Status: Implemented.

Flow:

- Registration hashes passwords with bcrypt, creates customers by default, and can create vendor users with an initial vendor profile.
- Login verifies password, rejects inactive users, creates a persisted refresh token, and clears failed-login counters.
- Refresh validates both the JWT refresh token and the persisted database token.
- Logout removes the refresh token.
- TSOA injects `expressAuthentication` into secured routes and attaches `req.user`.

Notes:

- Access tokens expire in 15 minutes and refresh tokens in 7 days, matching the spec.
- Refresh tokens are stable on refresh to avoid cross-tab race conditions.
- Failed login tracking uses Redis or memory store under tests.

### Cart Management

Files:

- `src/modules/cart/cart.controller.ts`

- `src/modules/cart/cart.dto.ts`
- `src/entities/Cart.ts`

Status: Implemented.

Flow:

- `GET /cart` creates or returns the active user cart.
- `POST /cart/items` locks the product row, checks stock, snapshots unit price, and merges quantities.
- `PUT /cart/items/{itemId}` updates quantity after stock check.
- `DELETE /cart/items/{itemId}` removes an item.
- `DELETE /cart` clears the cart.

Notes:

- Price snapshotting matches the spec.
- The product lock on add-to-cart helps reduce oversell races.

### Checkout, Payments, And Orders

Files:

- `src/modules/orders/*`
- `src/modules/payments/*`
- `src/config/paystack.ts`
- `src/entities/Order.ts`
- `src/entities/OrderItem.ts`

Status: Implemented.

Flow:

- `POST /orders/checkout` validates cart contents, snapshots items, creates a pending order, initializes Paystack, stores reference/payment URL, then clears the cart.
- `POST /payments/webhook` verifies Paystack signature, processes charge success events, marks orders paid, stores transaction ID, and decrements stock.
- `GET /orders` returns customer order history.
- `GET /orders/{id}` lets customers view their own orders and admins view any order.
- `GET /orders/vendor/my-orders` returns orders containing the vendor's products.
- `POST /orders/refund` lets admins refund paid orders.
- `GET /orders/admin/all` now enforces admin authorization.

Refactor:

- Webhook verification now signs the raw request body captured before JSON parsing.
- Checkout tax now uses configured `TAX_RATE`.
- Static order routes now generate before `GET /orders/{id}`.

Notes:

- There is also an admin-module order list at `GET /admin/orders`; the `/orders/admin/all` route is somewhat duplicative.

### Vendor Onboarding

Files:

- `src/modules/vendors/*`
- `src/modules/payments/*`
- `src/modules/uploads/*`
- `src/entities/VendorProfile.ts`
- `src/entities/VendorDocument.ts`
- `src/entities/VendorOnboardingFee.ts`

Status: Implemented with a registration-flow variation.

Flow:

- Vendor registration creates a `VendorProfile` with `pending_payment`.
- `POST /vendors/pay-fee` initializes Paystack onboarding payment.
- Paystack webhook calls `confirmFeePayment`, marks the fee paid, and advances the vendor to `pending_review`.
- Vendors submit documents after payment.
- Admins list pending vendors, view documents through fresh signed URLs, approve, reject, or suspend.
- Rejected vendors can reapply without a new fee for 3 months.

Spec alignment:

- State machine statuses match the spec.
- Document upload uses private S3 object keys and signed download URLs.
- Current API starts onboarding through vendor registration plus `/vendors/pay-fee`, not a separate `POST /vendors/apply` endpoint.

Needs product/design decision:

## Future Recommendations

- Adopt `AppError` consistently across services to remove legacy `Error` objects with mutable `status`.
- Reuse `getPaginationParams` across modules to reduce duplicate page/limit math.
- Add explicit role scopes or reusable service guards for all admin/vendor-only routes.
- Add integration tests for product route shadowing, order admin route shadowing, and public pending-product detail.
- Consider moving duplicated admin order functionality into a single admin route and deprecating `/orders/admin/all`.
- Add migration-backed cleanup for vendor document storage so only `fileKey` is persisted for private documents.
- Add a dedicated vendor analytics module.
- Add Docker Compose and PM2/process-manager files if they are still part of the deployment target.
